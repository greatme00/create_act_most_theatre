# Журнал актёра

**Информационная система для автоматизации учёта работы артистов, расчёта вознаграждения и формирования закрывающих документов.**

Система автоматизирует полный цикл работы с данными артиста: от регистрации спектакля или репетиции до расчёта месячного вознаграждения и формирования акта сдачи-приёмки оказанных услуг.

Пользовательский интерфейс реализован в Telegram. При этом Telegram является только интерфейсом взаимодействия: бизнес-логика, данные, расчёты, роли пользователей, настройки и формирование документов реализованы внутри системы.

---

## Задача

Учёт работы артистов включает большое количество повторяющихся операций:

- внесение спектаклей и репетиций;
- расчёт количества расчётных единиц;
- применение индивидуальных расценок;
- подсчёт итоговой суммы за период;
- подготовка закрывающих документов;
- исправление ошибочных записей;
- административное управление пользователями и настройками.

Система объединяет эти операции в единый процесс и минимизирует ручной ввод и расчёты.

---

## Основные возможности

### Учёт спектаклей и репетиций

Пользователь добавляет события через кнопочный интерфейс.

- дата выбирается через календарь;
- время выбирается с шагом 15 минут;
- стоимость спектакля рассчитывается автоматически;
- ошибочные записи можно удалить;
- незавершённое действие можно отменить;
- система учитывает контекст уже существующих записей.

Название роли при добавлении спектакля не требуется. Если спектакль с таким же названием уже добавлен на ту же дату, система дополнительно запрашивает время показа.

### Бизнес-правила расчёта репетиций

Продолжительность репетиции автоматически преобразуется в расчётные единицы:

| Продолжительность | Расчёт |
|---|---|
| До 3 часов включительно | 1 |
| Более 3 и до 9 часов | 2 |
| Более 9 часов | 3 |
| Время не указано | 1 |

Расчёт выполняется автоматически на основании введённых данных.

### Расчёт вознаграждения

Для каждого пользователя могут быть заданы индивидуальные расценки по категориям работы.

Система автоматически рассчитывает стоимость и формирует итог за выбранный месяц:

- количество спектаклей;
- количество репетиций;
- количество расчётных единиц;
- общая сумма.

### Формирование документов

На основании накопленных данных система формирует акт сдачи-приёмки оказанных услуг в формате Word.

При формировании документа выполняются:

- агрегация данных за период;
- группировка однотипных услуг;
- объединение дат;
- расчёт итоговой суммы;
- преобразование суммы в текстовый формат;
- формирование документа по заданному шаблону;
- использование разных вариантов текста в зависимости от профиля исполнителя.

### Профиль исполнителя

Система хранит данные, необходимые для расчётов и формирования документов:

- ФИО;
- реквизиты договора;
- статус исполнителя (самозанятый или физлицо по ГПХ);
- пол;
- индивидуальные расценки.

Пол может определяться автоматически по ФИО с возможностью ручного изменения.

### Напоминания

Каждый день в 10:00 по московскому времени система отправляет пользователю персональное напоминание о спектаклях и репетициях на следующий календарный день.

## Административный контур

Система содержит отдельный набор функций для администратора.

### Управление пользователями

Администратор может:

- просматривать список пользователей;
- изменять данные профиля;
- изменять реквизиты договора;
- изменять статус исполнителя;
- изменять пол;
- удалять пользователя вместе с его данными;
- назначать и отзывать права администратора.

### Массовые рассылки

Администратор может отправить сообщение всем пользователям. Система отображает прогресс выполнения операции и формирует итоговый отчёт.

### Управление шаблонами актов

Текст акта можно редактировать непосредственно через интерфейс системы.

Предусмотрены:

- редактирование отдельных блоков документа;
- разные варианты текста для разных профилей исполнителей;
- предпросмотр;
- проверка используемых плейсхолдеров;
- восстановление текста по умолчанию.

Таким образом, изменение содержания документа не требует изменения программного кода.

## Архитектура

Проект разделён на отдельные модули по зонам ответственности:

```text
├── bot.py                  # точка входа
├── config.py               # конфигурация и расчётные параметры
├── database.py             # работа с данными и миграции
├── act.py                  # генерация Word-документов
├── keyboards.py            # пользовательский интерфейс
├── utils.py                # вспомогательная логика
├── env.py                  # переменные окружения
│
├── handlers/
│   ├── common.py           # общие сценарии
│   ├── user.py             # спектакли и репетиции
│   ├── prices.py           # управление расценками
│   ├── month.py            # итоги месяца и документы
│   ├── profile.py          # профиль исполнителя
│   ├── admin.py            # административные функции
│   ├── act_editor.py       # редактор шаблона акта
│   ├── broadcast.py        # массовые рассылки
│   └── fallback.py         # обработка неизвестных сообщений
│
├── requirements.txt
└── .env.example
```

## Ключевые проектные решения

### Отделение интерфейса от бизнес-логики

Telegram используется как пользовательский интерфейс, а основные правила расчёта и обработки данных находятся в отдельных модулях. Это позволяет изменять пользовательские сценарии и бизнес-правила без смешивания их с логикой отображения интерфейса.

### Формализация бизнес-правил

Правила расчёта репетиций, определения стоимости, группировки услуг и формирования документов реализованы как отдельная логика системы, а не как ручные операции пользователя.

### Настраиваемые документы

Текст акта вынесен в управляемые настройки. Администратор может изменять содержимое документа через интерфейс без изменения исходного кода.

### Разделение ролей

Пользовательский и административный контуры разделены. Администратор получает дополнительные функции управления пользователями, рассылками и документами.
